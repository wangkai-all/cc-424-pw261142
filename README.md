# dq — 数据质量规则命中分析系统

同一条记录可能命中多条质量规则。本系统对**虚构数据**执行**真实规则计算**，
同时展示**各规则命中**与**去重后的总体影响**——朴素求和被明确标注为无效总数，
绝不把各项相加当总数。

纯 Python 标准库 + 原生 JS，无第三方依赖。

## 三个独立运行的组件

| 组件 | 进程 | 职责 |
|---|---|---|
| 规则执行器 | `python -m dq.executor` | 对当前输入执行规则，把命中明细作为一个 run 报告给明细库 |
| 命中明细库 | SQLite（`dq/store.py`） | 保存全量命中明细；以 (规则版本, 输入版本) 纪元决定贡献生效/撤回/拒绝 |
| 分析发布端 | `python -m dq.publisher` | 两阶段发布分析快照（暂存→原子提交），可崩溃恢复 |

网页端（`python -m dq.server`）只做查询、可视化和触发，不代替上述进程计算。

## 快速开始（从空目录）

```bash
python3 -m dq.server --port 8000     # 首次启动自动生成虚构数据、执行规则、发布快照
# 打开 http://localhost:8000
```

无头演示完整流水线（含迟到回报、发布中断模拟）：

```bash
python3 -m dq.cli demo --db data/dq.db --dir data/published
```

测试：`python3 -m unittest discover -s tests -v`

## 核心机制

### 纪元与撤回（retraction）
- 修改规则 → 规则版本 +1 → 旧版本 run 全部 **retracted**，命中贡献立即撤回，规则进入「待重算」
- 修订输入 → 输入版本 +1 → 全部 run 撤回
- 执行器迟到（报告时世界已前进）→ 报告被拒绝为 **stale**，不会污染当前分析
- 明细行本身不被改写，只改 run 状态，历史可审计

### 精确 vs 近似，压缩的取舍
- **全量命中明细**是事实来源；**Roaring 位图**（`dq/roaring.py`，容器化精确压缩）
  由明细推导：支持交集（追溯到具体记录）、支持合法删除（`discard`）
- **HyperLogLog**（`dq/hll.py`）只给**近似**并集基数：页面上永远带「近似」徽标和误差界，
  不与精确值混排；它不可删除成员——合法删除后只能重建（系统会标记并完成重建）
- 合法删除（隐私场景）：抹除记录本体 + 全部命中明细行，精确集合同步收缩

### 分析内容
- 各规则精确命中数、去重并集（精确）、被重复计数 = 朴素和 − 并集
- 命中组合（记录按规则签名归类，各组合之和 = 去重总体，可核对）
- 两两交集矩阵（精确，点击追溯到记录）
- 压缩率：Roaring 字节 vs 原始 id 列表

### 网页功能
- **总览**：去重总体（hero）、无效朴素和（删除线）、HLL 近似（标注）、压缩率、两两交集热图、发布一致性
- **规则**：查看/修改/新增/删除规则（修改即新版本 + 撤回）
- **重叠组合**：组合 → 精确交集 → 具体记录 → 原始记录详情
- **记录**：浏览、定位原记录、合法删除
- **流水线与模拟**：执行规则、**延迟执行器**（睡眠期间改规则 → stale）、**模拟迟到回报**、
  修订输入、发布、**模拟发布中断**、恢复、事件日志

## 布局

```
dq/
  dataset.py    虚构数据生成与输入修订（确定性种子）
  rules.py      规则种类与求值（真实计算，非筛选器）
  store.py      命中明细库：纪元、撤回、stale 拒绝、删除、快照
  roaring.py    精确压缩集合（容器化位图）
  hll.py        近似基数（HyperLogLog）
  analysis.py   各规则/去重并集/组合/交集/压缩率
  executor.py   规则执行器（独立进程）
  publisher.py  分析发布端（独立进程，两阶段提交）
  server.py     查询/可视化/触发端
  cli.py        init / demo / reset
ui/             单页应用（原生 JS）
tests/          核心正确性测试
```
